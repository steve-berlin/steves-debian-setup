# installers/

Shared conventions — re-exec guard, `set -euo pipefail`, standard modes, `--dry-run`, the `set -e` AND-list trap, ELI11 docs — are in the root `CLAUDE.md`. This file is per-script gotchas only.

## `utils.sh` — bulk bootstrap

Resolves every dep referenced by `~/.zshrc`: apt packages, oh-my-zsh + plugins, fzf, user toolchains (rustup, rbenv, atuin, starship, nvm, deno, bun, pyenv), Go + neovim tarballs, third-party installers (brave, waydroid), pip tools, flatpak apps, Claude Code, caveman, NordVPN, tmux config, helper scripts, XFCE + KDE keybindings, EasyEffects presets. Sections 1–15 match `check-setup.sh`'s verification order; step 14 is a no-op stub (debloat moved to `debloat_scripts/`). `shr` helper prints a short summary in `--dry-run` instead of the whole pipe for curl-piped installers + heredoc writes.
- **Step 0** offers a y/N prompt to delete `installers/discontinued/` (interactive tty only; `--dry-run`/piped runs keep it). **Dead code** — the directory was deleted in `baaa81c`, so the guarding `[[ -d $disc ]]` never fires. Harmless, re-arms if the directory returns; delete it if that bothers you.
- **Step 8** seeds `~/.config/nvim/` from vendored `nvim-config/` via `rm -rf` + `cp -a` (was `git clone LazyVim/starter`); overwrites unconditionally.
- **Step 9b** pip-installs `yewtube` on its **own** pip line — it pins `httpx<0.28`, and folding it into step 9's `yt-dlp tldr platformio` line would let one resolver conflict take all four down. Console entry point is **`yt`**, not `yewtube` (the name `check-setup.sh` step 8 probes). Runtime deps already covered: `mpv` (step 1 apt), `yt-dlp` (step 9).
- **Step 10 flatpaks**, all `--user`: Organic Maps, Session, SimpleX Chat (`chat.simplex.simplex`), EarTag (`app.drey.EarTag`), Telegram (`org.telegram.desktop`); `check-setup.sh` step 9 probes each with `flatpak info --user`. Telegram from Flathub, not Debian's `telegram-desktop`: the server enforces a minimum client version and eventually refuses a stale build outright. EarTag from Flathub, not Debian's `eartag` (trixie ships 0.6.5) — keeps every GUI app on one update path.
- **caveman (step 10b′)** — [JuliusBrussee/caveman](https://github.com/JuliusBrussee/caveman) Claude Code plugin via `curl … install.sh | bash -s -- --non-interactive`. Idempotency guard is the `~/.claude/.caveman-active` flag file (not `have` — it's a plugin, not a PATH binary). Needs node ≥ 18: `source_nvm` sources `nvm.sh` (guarded against `set -u` fallout), then `nvm install --lts` only when no `node` is on PATH. Uninstall out-of-band: `utils.sh --uninstall-caveman` (runs `npx -y github:JuliusBrussee/caveman -- --uninstall`, then exits before the install flow) — a dedicated flag, since utils.sh has no whole-stack teardown.

**Package pruning (steps 1c/1e)**, right after the apt installs. Both idempotent (skip when already gone) and dry-run safe; `check-setup.sh` mirrors them.
- **1c** purges `atmel-firmware` (Atmel at76c50x USB 802.11b dongles — dead weight on Intel wifi) only after `atmel_present()` clears: nothing bound under `/sys/bus/usb/drivers/at76c50x_usb`, module absent from `lsmod`, no `lsusb` match. Any hit keeps the package with a warning so real firmware is never yanked.
- **1e** purges `foliate` + `autoremove --purge` for the gjs/webkit stack it drags in; `mupdf` from step 1 covers EPUB.
- **1d is removed — do not reintroduce it.** It repointed `/bin/sh` at `zsh` and purged `dash`; it bricked the box on 2026-08-02. `dash` *owns* `/bin/sh` on trixie (`dash.prerm` carries `remove_divert /bin/sh`; `dpkg -S /bin/sh` only comes up empty *after* a failed purge truncates `dash.list`). dpkg deletes `/bin/sh` — zsh symlink and all — partway through the purge, then execs `dash.postrm`, whose `#!/bin/sh` shebang now has no interpreter → exit 1. Result: `dash` wedged `iH`, `/bin/sh` gone, every `#!/bin/sh` script dead (all dpkg maintainer scripts, pending `debianutils`/`man-db`/`menu` triggers), `set -e` killing utils.sh before its reassert line. No ordering survives — the delete happens *between* the two commands, inside dpkg. Recovery: `sudo ln -sf /usr/bin/bash /bin/sh` → `sudo apt-get install -y --reinstall dash` → `sudo dpkg --configure -a`. Matching `check-setup.sh` assertions (`np dash`, `/bin/sh -> *zsh`) are gone too.

**PDF/EPUB stack — there is no zathura mupdf backend on trixie; don't put one back in the apt line.** Neither `zathura-pdf-mupdf` nor `zathura-mupdf` exists (`apt-cache pkgnames | grep mupdf` on MX 25 → only `mupdf`, `mupdf-tools`, `libmupdf-dev`, `libmupdf25.1`, `python3-{mupdf,pymupdf}`). Debian dropped the plugin, kept the engine. One bad package name makes the whole single `apt-get install` line exit non-zero, `set -e` aborts, and **nothing in step 1 installs**. So step 1 ships `zathura-pdf-poppler` + `zathura-djvu` (PDF/DjVu in zathura) and the standalone `mupdf` viewer (EPUB/XPS/CBZ), plus `ncdu`. Two readers instead of one is the cost of the missing plugin. **If you ever drop `mupdf`, drop step 1e in the same commit** or the box ends up with no EPUB reader. Rebuilding the plugin from `libmupdf-dev` + `pwmt/zathura-pdf-mupdf` needs its own installer and a pinned mupdf — ABI churn against 25.1 is why Debian dropped it.

## `check-setup.sh` — post-bootstrap verifier

Mirrors `utils.sh` step-for-step, prints `[OK]`/`[FAIL]`, exit 0 if all pass. Run after `utils.sh` or after any upgrade touching the GPU stack (the iGPU/nouveau check catches regressions). No flags, no args, read-only. Walkthrough: `docs/check-setup-eli11.md`. **`set -u` only, not `set -euo pipefail`** — a failed check is the result, not a script error; `set -e` would abort at the first missing package and swallow the other ~80 answers. Exit status is the trailing `[ "$F" -eq 0 ]`.
- **Steps 14–15 fail by design on a box that only ran `utils.sh`.** They assert debloat results (gimp/vlc/nvidia gone, nouveau blacklisted, iGPU renderer) and debloat is opt-in in `debloat_scripts/`. Not a bug; the exit code is still 1.
- **Step 7 checks `~/.config/nvim/{init.lua,lazy-lock.json}`, not the directory** — `utils.sh` step 8 `rm -rf`s the directory first, so a directory that exists without the lockfile means the `cp -a` died mid-copy. (Added 2026-08-29; the old comment claiming step 8 was "commented out" was stale.)
- **Step 16 requires at least one `*.json` under `~/.config/easyeffects/output`**, not just the directory — EasyEffects creates that directory itself on first launch, so a bare-directory check would pass with no presets installed.
- **caveman is checked by its `~/.claude/.caveman-active` flag file**, mirroring `utils.sh`'s own idempotency guard — it's a plugin, not a PATH binary.
- **Step 17 is a credential scan, not a setup check.** Greps the six shell rc files for known token shapes (`gh[pousr]_`, `github_pat_`, `sk-ant-`, `AKIA`) plus any `*_TOKEN|_KEY|_SECRET|PASSWORD=` whose value starts alphanumeric — that last condition is what suppresses `FOO="$BAR"`, `FOO=` and `FOO=""`. Comments are filtered *after* `grep -n` so reported line numbers stay real. **Prints line numbers only, never values.** Exists because `~/.zshrc` symlinks into `steves-cli-setup`, making a token pasted there a tracked file — that happened 2026-09-05, and on its first run the scan found a second, unrelated PAT in `~/.zshrc.local`.

## `install-mx-frugal.sh` — install Linux with no USB stick (frugal boot as install medium)

Turns an MX/antiX ISO on disk into a GRUB entry so a box with no working USB port can reach a live session and run MX's installer. Loop-mounts the ISO, copies its `/antiX` dir (`vmlinuz`, `initrd.gz`, `linuxfs`) to `<target>/<name>/antiX` (default `/frugal`), writes `/etc/grub.d/42-mx-frugal-<name>`, runs `update-grub`. Modes: bare / `--reinstall` (wipe + recopy payload) / `--uninstall` / `--dry-run`, plus `--target DIR`, `--name NAME`, `--sha256 SUM|FILE`. Workflow: run it → reboot into "MX live (frugal, install medium)" → install onto a **different** partition than the payload → `--uninstall`. **No persistence on purpose** — throwaway install medium, not a frugal *system*; live changes die at reboot like the USB stick it replaces.
- **Boot params are `bdir=` + `buuid=`, not `fromiso=`.** `bdir` = directory holding `linuxfs`, relative to the **partition root** (a payload at `/frugal/MX/antiX` on a separate `/data` mount is `bdir=/frugal/MX/antiX` only when `/data` *is* the mount — `rel_bdir` strips the mountpoint prefix). `buuid` = that partition's filesystem UUID. Same pair antiX's own `grub.entry` uses. `from=all` is required: live-init defaults to `from=usb,cd` and never probes an internal disk. `fromiso=` is deprecated upstream and disables live features.
- **Never formats or repartitions.** Target must exist and be mounted. `probe_target` hard-fails on non-`ext2/3/4|xfs|vfat` filesystems and on `crypt`/`lvm` device types — GRUB and live-init both reach the payload by plain UUID. Free space must cover payload + 256 MiB.
- **`local dir=$1 probe=$dir` does not work.** Bash expands every word of the `local` line before assigning, so `$dir` reads unset and `set -u` aborts. Split into two statements (done — don't "tidy" it back).
- **Secure Boot warning is not cosmetic** — the entry boots an unsigned kernel; SB firmware refuses it. Warns via `mokutil --sb-state` when available.
- `--dry-run` mounts nothing and creates no tmpdir, so it skips the ISO-layout and free-space checks — plan only.
- **Never boot-tested.** Verified: `bash -n`, `--help`, dry install/uninstall, `rel_bdir` stripping. Keep a known-good boot entry reachable on first real use.

## `install-anki.sh` — official upstream tarball

Debian's `anki` lags by years. Since 25.07 the official Linux delivery is the **anki-launcher** tarball — a tiny launcher that pulls the real app on first run. Script picks the newest GitHub release carrying the launcher asset, hands off to Anki's installer (writes `/usr/local`). Decks at `~/.local/share/Anki2` untouched. Deps: `bash curl tar` (with `--zstd`, i.e. modern GNU tar or `apt install zstd`), `awk sudo`. No `jq` — release lookup is `curl | awk`. Asset regex `anki-launcher-.*-linux[.]tar[.]zst$` (use `[.]`, not `\.` — `awk -v` strips one backslash). GitHub anon API limit 60/hr per IP; symptom is an empty `url`. Layout: `/usr/local/bin/anki`, `/usr/local/share/anki/`, `~/.local/share/Anki2/` (decks/media), `~/.cache/Anki2/` (downloaded app, regeneratable). Gotchas — do not reintroduce:
1. **Don't `exit` from the awk parsing the GitHub API.** Closing the pipe early SIGPIPEs curl; with `pipefail` the `url=$(curl … | awk …)` substitution silently fails. Use a `seen` flag and let curl finish writing.
2. **Don't `local tmp` for the scratch dir referenced by the EXIT trap.** The trap fires after the function returns, the local is gone, and `set -u` blows up with `tmp: unbound variable`. Keep `tmp` at script scope, reference as `${tmp:-}`.

## `install-music-dl.sh` — pipx-managed music/audio downloader stack

`streamrip` (`rip`) + `spotdl`, plus `yt-dlp` when nothing else owns it. apt-installs `pipx` + `ffmpeg` if absent. Modes: bare (install *or* `pipx upgrade`) / `--reinstall` (`pipx install --force`, rebuilds each venv) / `--uninstall` (drops the venvs only) / `--dry-run`. Walkthrough: `docs/install-music-dl-eli11.md`. Deployed 2026-08-24: streamrip 2.1.0, spotdl 4.5.2, yt-dlp 2026.8.19, all on Python 3.13.5.
- **pipx, not `pip3 --break-system-packages --user`** (utils.sh step 9). Not a style preference — the two apps share 16 dependencies and **conflict on one**: streamrip pins `pillow` 10.4.0, spotdl needs 12.3.0. A shared site-packages cannot hold both; whichever installs second wins and the other breaks at runtime. Same failure step 9b splits `yewtube` onto its own pip line to dodge. pipx gives each app its own venv, so the class of bug disappears instead of being worked around.
- **Python window is `>=3.10, <3.15`** — streamrip/yt-dlp floor at 3.10, spotdl's metadata caps at `<3.15`. Preflight checks it via `awk`, because outside that window pipx fails deep in the build with a useless traceback.
- **`yt-dlp` is adopted, never clobbered.** pipx's shim path *is* `~/.local/bin/yt-dlp` — exactly where utils.sh step 9's pip line writes. `pipx install yt-dlp` would refuse ("not associated with pipx") or, with `--force`, shadow a pip package that rots in `~/.local/lib` and returns on the next utils.sh run. So: `pipx upgrade` if pipx already owns it, skip with a note if any other copy is on PATH, fresh `pipx install` only if nothing provides it. Costs nothing — spotdl vendors `yt-dlp` as a *library* in its own venv and never shells out to the CLI; streamrip doesn't use yt-dlp at all (aiohttp + deezer-py + ffmpeg). Only interactive `yt-dlp` runs care which copy wins PATH.
- **`warn_if_shadowed` is not cosmetic.** On this box `~/.local/bin` sorts *after* `/usr/bin` in PATH, so apt's `/usr/bin/yt-dlp` wins and `pipx upgrade yt-dlp` bumps a binary the shell never reaches — a successful upgrade that changes nothing. Warns with both fixes (reorder PATH in `~/.zshrc`, or `sudo apt purge yt-dlp`). Distro yt-dlp goes stale fast; YouTube extractor breakage is the symptom.
- **Writes no credentials, by design.** streamrip reaches lossless by logging in *as you*: Tidal/Qobuz need a paid lossless plan, Deezer free is 128k MP3, SoundCloud is open. Script prints `rip config open` and stops. `--uninstall` leaves `~/.config/streamrip/` alone for the same reason, and leaves `pipx`/`ffmpeg` alone as shared deps.
- **`curl-cffi` is injected into the `yt-dlp` venv** (`inject_impersonation`), giving `--impersonate chrome` TLS/JA3 spoofing. Not optional here: NordVPN autoconnect parks traffic on a shared exit IP 24/7, which is exactly what anti-bot layers challenge — a bare `yt-dlp` on a CDN-fronted host returns `Got HTTP Error 403 caused by Cloudflare anti-bot challenge`. spotdl needs no inject: it already ships curl-cffi 0.15.0 transitively. **Detect with an import check against the venv's interpreter, not `pipx list --include-injected`** — that output lists only pipx's own injects, so for spotdl pipx simultaneously refuses ("already seems to be injected") and reports `injected_packages: []`.
- **Impersonation does not beat YouTube's bot gate.** Verified 2026-08-24 from a Senegal exit node: Cloudflare 403s cleared, but YouTube still answers `Sign in to confirm you're not a bot` with or without `--impersonate`. That one needs cookies — `yt-dlp --cookies-from-browser firefox`, `spotdl --cookie-file`. `post_notes` prints both. Consequence: **spotdl's audio leg is blocked while the VPN is up** even though its Spotify metadata leg works fine.
- **Tested 2026-08-24 on the deployed box.** yt-dlp: full download → ffmpeg → FLAC 44.1kHz stereo, verified with `ffprobe` (public-domain Wikimedia source). spotdl: Spotify metadata resolves (`spotdl save` returned artist/album correctly), YouTube audio leg blocked per above. streamrip: `rip config path` materializes `~/.config/streamrip/config.toml` with every credential field empty, and `rip url` on Qobuz/Deezer prompts for creds then exits `Aborted!` cleanly on closed stdin. Not testable without a paid subscription: streamrip's actual download path. **`rip search` needs a real TTY** — it opens an interactive picker and dies with `OSError: [Errno 6] ... '/dev/tty'` when run non-interactively; use `rip url` in scripts.
- **Not mirrored in `check-setup.sh`** — that verifier mirrors `utils.sh` only (same as `install-anki.sh`/`install-ly.sh`, which has its own `check-ly.sh`).
- **SpotiFLAC is deliberately not here.** Its core ships no providers at all ("no built-in download provider and no default extension source"); every Tidal/Qobuz/Amazon/Deezer backend is a third-party extension the maintainer explicitly does not review, and the ones advertising "no account required" relay through someone else's paid credentials. Core alone is `pipx install SpotiFLAC` and does nothing without extensions. streamrip covers the same four services with your own subscription — that's the supported path.

## `install-ly.sh` — build & install the Ly TUI display manager

Ly isn't packaged for MX/Debian and needs a matching Zig to build: script fetches a pinned Zig tarball (`ziglang.org`) + pinned Ly tag (`fairyglade/ly`, submodules zigini+clap), builds with `zig build`, then `sudo zig build installsystemd` (v1.0.3 has no `-Dinit_system`; `installexe` writes `/usr/bin/ly` + `/etc/ly/`, `installsystemd` dependOn's it and adds `ly.service`). Pins: `LY_VERSION=1.0.3 ZIG_VERSION=0.13.0` (Ly 1.0.x needs Zig 0.13; v1.0.3 is the last GitHub release — newer Ly moved hosts and wants Zig 0.16). Stamp `/usr/local/share/ly.version` makes a same-version re-run a no-op (avoids clobbering `/etc/ly/config.ini`). Modes: bare / `--reinstall` / `--uninstall` / `--dry-run`, plus `--default` / `--no-default`.
- **Default-DM switch is opt-in via y/N prompt.** Only on "yes" does `make_default` disable the live `display-manager.service` + `getty@tty2.service` (Ly owns tty2) and `systemctl enable ly.service`. `--default`/`--no-default` skip the prompt; non-interactive stdin defaults to *no* with a warning so a piped run can't silently swap the DM.
- **`installsystemd` runs under sudo, the user-mode `zig build` first** — compile errors surface as the user before root touches the system; the install step writes absolute paths (no `DESTDIR`), so it needs root. The root build drops root-owned files into `$tmp/.zig-cache`, so the script `sudo chown -R`s `$tmp` back afterward or the user-mode EXIT-trap `rm -rf` can't clean it.
- **Preflight checks build headers via `dpkg -s libpam0g-dev libxcb-xkb-dev`** (Zig links Ly against system PAM+XCB); hard-fails on missing `git/curl/tar/sudo/systemctl`; arch guard maps only `x86_64`/`aarch64`. **Under `--dry-run` every preflight miss downgrades to `warning:`** (local `miss` helper) — a dry-run must still print its plan, and you'd typically dry-run before installing the toolchain.
- **`--uninstall` re-enables `getty@tty2` and removes Ly's files but does NOT re-enable a DM** — prints the `systemctl enable sddm` reminder instead; guessing the prior DM and silently re-wiring `display-manager.service` is how you brick a login.
- **Login crashes right after resume are NOT a Ly bug** — see `fix-suspend-freeze.sh`. An earlier `/etc/pam.d/ly` rewrite was a misdiagnosis (reverted): `pam_systemd` was fine, the scope creation was losing a race against the freeze.

## `check-ly.sh` — read-only health check for the whole Ly stack

Diagnoses every known Ly failure mode so a broken login is caught here, not at a black screen. Mutates nothing; `[OK]`/`[FAIL]` plus `[WARN]` (advisory/historical, never fails the run) and `[--]` (info). Exit 0 iff no FAILs. Sections: **binary & version** (`/usr/bin/ly` exec, `ly --version` — prints to **stderr** — vs the `/usr/local/share/ly.version` stamp); **config & setup scripts** (`config.ini`, `xsetup.sh`/`wsetup.sh` executable, save dir — Ly writes `save_file` as root, so only existence matters); **config-referenced commands** (every binary named in `config.ini`: `x_cmd`/`xauth_cmd`/`mcookie_cmd`/`term_*`/`shutdown_cmd`… — a missing one is a silent login failure); **login sessions available** (≥1 `.desktop` in xsessions/wayland-sessions); **service wiring** (`ly.service` is `display-manager.service`, enabled, no getty racing its tty); **PAM stack** (recurses `/etc/pam.d/ly` includes one level, verifies every referenced `pam_*.so` exists; `-`-prefixed optional lines don't fail); **logind/XDG_RUNTIME_DIR** (systemd PID 1, logind active, `libpam-systemd`, `pam_systemd.so`, `/run/user/<uid>` ownership); **suspend-freeze fix** (var honored + drop-in on all four sleep services); **journal scan** (counts + newest timestamp for `frozen` session-scope failures, pam_systemd create-session failures, Wayland socket/lockfile errors, PAM auth failures, real ly.service crashes).
- **Journal scan needs system-journal read.** Reader picked in order: passwordless `sudo -n`, membership in `adm`/`systemd-journal`, interactive `sudo -v`. None available → one WARN (not FAIL) telling you to re-run with sudo. Historical hits surface as WARN by design — that's how you confirm the fix landed.
- **`ly --version` and the freeze-var probe both need care under `pipefail`.** Version parse uses `2>&1`; the `strings`-of-`systemd-sleep` probe captures into a var rather than `strings | grep -q`, which would SIGPIPE `strings`.

## `fix-suspend-freeze.sh` — stop logins crashing after suspend/resume

systemd 256+ freezes `user.slice` (via `systemd-sleep`) on sleep and thaws on resume. A login landing in the un-thawed window can't get its session scope: `Cannot start frozen unit session-N.scope` → `Failed to create session: Job … failed with 'frozen'`. No scope → no `/run/user/<uid>` → the session dies with **"Can't open Wayland socket"** / **"Unable to open lockfile"**, surfacing as **"Can't authenticate user"**. Intermittent because it only bites inside a suspend/resume window. **Not Ly-specific** — getty `login` hits the same race. Fix: drop-in `no-freeze-user-sessions.conf` on all four sleep services (`systemd-{suspend,hibernate,hybrid-sleep,suspend-then-hibernate}.service`) setting `Environment="SYSTEMD_SLEEP_FREEZE_USER_SESSIONS=false"` — documented systemd knob, honored since v256, skips the freeze so there's no thaw to race. `systemctl daemon-reload` after; effective next sleep, no reboot. Modes: bare / `--reinstall` (== install) / `--uninstall` / `--dry-run`.
- **Preflight greps the actual `systemd-sleep` binary for the var name** so an older systemd fails loud instead of writing a silent no-op drop-in. Captures `strings` output into a var, not `strings | grep -q` (SIGPIPE under `pipefail` → false negative).
- **Verify**: `systemctl show systemd-suspend.service -p Environment`; after the next resume the journal logs `User sessions remain unfrozen on explicit request` and no new `'frozen'` errors.

## `fix-mount.sh` — diagnose and repair a failing mount

For `mount: /dev/sdb: mount point not mounted or bad option.` — util-linux's catch-all when it can't line up a (device, filesystem, mountpoint) triple. Usage `fix-mount.sh [-o OPTS] [-y] [--dry-run] <target> [mountpoint]`; target may be a device, `/dev/disk/by-*` symlink, `UUID=`/`LABEL=`/`PARTUUID=`/`PARTLABEL=`, a bare label/uuid, or a mountpoint. Exit 0 mounted/already mounted/dry-run, 1 unfixable, 2 bad args. Walkthrough: `docs/fix-mount-eli11.md`. Deviates from repo convention: no `--reinstall`/`--uninstall` (nothing is installed). Read-only diagnosis first, then prompted fixes: `mkdir -p` the mountpoint, `modprobe`, `apt-get install` the driver package, mount with the corrected device + options, `-o ro` retry, `ntfsfix`. Detects: fstab entry in both directions, whole-disk-vs-partition, missing filesystem signature, LUKS/LVM/md-RAID/swap containers, driver loaded vs loadable vs absent, mountpoint missing/not-a-dir/non-empty, device busy.
- **`PATH=/usr/sbin:/sbin:$PATH` at the top is load-bearing.** `blkid`, `findfs`, `modprobe` and `fsck` are not on a normal user's PATH on Debian/MX; without this every probe silently returns empty and the diagnosis is wrong rather than absent.
- **Filesystem type comes from `lsblk`, not `blkid`.** `lsblk` reads the udev database and answers unprivileged; `blkid` would need root to re-read the superblock.
- **A `BLOCKED` cause stops the script** (encrypted volume, LVM PV, RAID member, no filesystem, no mountpoint given). It prints the command you'd run and exits 1 — it never guesses past something it can't safely handle. It never formats, repartitions, edits `/etc/fstab`, or runs `fsck` on its own.
- **`ntfsfix` prompts even under `--yes`** and refuses non-interactively: every other fix creates a directory or installs a package, that one writes to the filesystem. `--yes` means "skip routine prompts", not "repair my disk".
- **`uid=`/`gid=` are added automatically for vfat/exfat/ntfs** when the caller passes no `-o` — those filesystems store no Unix ownership, so a plain mount is root-owned and unwritable, which reads as a second failure later.

## patches/
- **`tmux-dim-inactive-panes.patch`** — origin chud-methodology (anonymous.4open.science/r/chud-methodology-1477). Adds `colour_dim()` to `colour.c`, a `dim_inactive` flag on `struct tty`, and hooks in `screen-redraw.c`/`screen-write.c`/`tty.c` that set/clear it around per-pane draws. Applied against the tmux 3.5a tarball, `patch --dry-run` first.
